# 核心方法：先读这份，再查仓库细节

本文件凝练自已经实际读取的参考仓库。开始制作、改造或审片前必须读完。不要用仓库名称、风格形容词或几张截图代替这些方法。

## 1. 把视频当成时间函数

每一帧都要能由时间 `t` 重新画出。网页、React、Canvas 和 WebGL 只是绘图工具，不是成片本身。

```text
讲解内容 → 统一时间轴 → render(t) → 逐帧图像 → FFmpeg → MP4
```

不要录实时播放的网页。实时录屏会受机器速度、加载状态和掉帧影响，也难以准确返修某一帧。

任意时间都要能直接跳转渲染。暂停、倒退、重播或只渲染中间一段时，结果仍应一致。

## 2. 先统一内容，再安排画面

先写清观众看完要理解什么。再核对事实、数字、图表和素材。不要用动效掩盖内容空缺。

把以下数据放进同一份时间轴：

- 旁白与字幕；
- 镜头起止时间；
- 画面主体与素材；
- 动画事件；
- 运镜与转场；
- 需要配音或音乐时的音频事件。

每句讲解都要有画面任务。讲到哪个对象，就显示、放大或移动到哪个对象。不要提前堆出后文全部内容。

每个镜头只承担一个理解任务。开头尽快进入主题，结尾完成收束。

## 3. 按信息关系选择镜头结构

### 连续场景或大画布

适合位置关系、因果链、流程和同一系统的逐步展开。让镜头在视觉锚点之间移动，保持观众的空间记忆。

大画布不是把整张小字网页慢慢缩放。只建当前内容需要的节点，进入新信息区时再揭示新内容。

### 独立镜头

适合话题切换、时空变化、对比和机制改变。用明确切点重置构图，不强求一镜到底。

两种结构可以混用。选择标准是理解成本，不是炫技。

## 4. 用运动解释，不用运动填时间

运镜要有目标：建立全貌、聚焦细节、跟随对象、展示关系或完成对比。

转场优先利用内容关系：图形形变、遮罩揭示、遮挡切换、匹配构图和镜头移动。转场前后的主体位置和运动方向要连续。

关键动作要有缓动、预备、跟随和短暂停顿。避免所有元素同时匀速出现，也避免无意义淡入淡出。

检查时不仅问“画面好不好看”，还要问“这段运动是否让讲解更清楚”。

## 5. 保持可读和统一

只保留必要的大号文字。删除装饰小字、角标、章节标签、无关中英对照和重复标题。

内容放不下时拆镜头，不缩字。字幕最多两行，避开主体，并保留完整阅读时间。

普通图标来自同一套图标库，默认 Lucide。不要用 emoji 或临时手绘路径充数。只有领域结构、图表和特殊主体才定制矢量图形。

用户素材优先。保持原始比例，确认裁切重点，记录外部素材来源和许可。

## 6. 建立可失败的渲染契约

### 新建 Remotion 工程

用帧号和视频配置计算时间。使用 `useCurrentFrame()`、`interpolate()`、`spring()` 和 `<Sequence>`。

禁止用 CSS transition、CSS animation 或 Tailwind 动画类驱动成片。素材进入 `public/`，通过 `staticFile()` 引用。

### 改造确定性 HTML 工程

先找到并保留原工程的接口。常见接口包括：

- `DUR` 或等价时长配置；
- `render(t)` 或 `renderAt(t)`；
- `READY` 或等价就绪标志；
- 事件、文字框和字幕检查接口。

只有字体、图片、脚本和必要数据加载完成后，才能设置就绪标志。

页面脚本错误、关键资源加载失败、浏览器崩溃或 WebGL 上下文丢失时，渲染必须失败并报告。不要继续输出看似完整的坏片。

### 所有路线共同遵守

- 固定随机种子；
- 不读取墙上时钟；
- 不依赖上一帧残留状态；
- 不依赖未加载完成的远程资源；
- 同一 `t` 的重复渲染结果一致；
- 支持只渲染指定时间或指定片段。

## 7. 用多轮证据迭代，不赌一次成片

完整流程如下，详细标准见 `review.md`：

1. 自检脚本、时间轴、素材和分镜。
2. 渲染每个镜头的开始、中间和结束帧。
3. 输出全片联系表和信息密集镜头的原尺寸帧。
4. 输出转场、快速动作和机制变化的连续帧条。
5. 渲染低清完整预览，覆盖整个时间轴。
6. 做一次独立评审；没有第二执行者时，用只看证据的新评审轮次代替。
7. 按影响列出问题，保留旧版，集中修复同一根因。
8. 局部重渲并检查受影响镜头及相邻转场。
9. 全量导出，再检查最终 MP4 的画面和技术参数。

至少进行两轮覆盖全片的检查。第一轮找结构和理解问题，第二轮确认返修没有引入新问题。

## 8. 如实描述检查范围

单张截图只能证明该帧的构图。连续帧条只能证明所取时间附近的运动。低清预览不能证明最终分辨率下的小字和边缘质量。

只有直接读取或播放完整视频时，才能说“完整看过成片”。只抽帧时，明确说检查了哪些时间点、镜头和连续区间。

自动检查未运行、缺少接口或无法读取时，状态是“未检查”，不是“通过”。

## 9. 需要更深细节时读真实仓库

先根据 `repositories.md` 选择项目，再读与当前问题直接相关的真实文件和许可。仓库索引本身不算读过项目。

- 导演、字幕阅读时长和渲染失败处理：`lemo-opuscar` 的 `DIRECTOR.md`、`TECHNIQUE.md`、`core/render/`。
- 科普 MG、大画布和独立评审：`mg-styles-15` 的 `prompts/19-paperclip.md`、`rubric.md`、`harness/render.mjs`。
- 多镜头联系表、连续帧条和分章验收：`opus-video-skills` 的 `skills/kinetic-reel/`。
- 全时间轴、动态样片和重播一致性：`opus-5-5-86-styles-in-motion` 的 `references/motion-delivery.md`。

不要无差别下载或执行整个仓库。不要复制原片题材、品牌和镜头组合。
