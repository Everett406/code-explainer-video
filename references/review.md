# 多轮检查、返修与最终验收

## 验收原则

先修影响理解的问题，再修装饰细节。用真实渲染结果说话，不用“专业”“电影感”“高质量”等形容词代替证据。

静态帧、连续帧、完整预览和技术检查各自证明不同事情，不能互相替代：

- 单张帧证明某个时刻的构图和文字。
- 连续帧条证明一段运动、转场或状态变化。
- 完整预览证明整片的节奏和信息衔接。
- 最终 MP4 检查证明实际交付文件的编码、解码和音画状态。

检查未运行、接口缺失或文件无法读取时，标记“未检查”，不能算通过。

## 每轮留下记录

在工程中保存 `review/round-01.md`、`review/round-02.md` 等记录。每轮写清：

```text
检查版本：
检查范围：
证据文件：
发现的问题：时间点｜可见现象｜原因｜修法｜优先级
本轮修改：
复查结果：
仍未检查或仍未解决：
```

保留返修前的版本或证据。不要覆盖后只剩一句“已优化”。

## 第 0 轮：渲染前自检

先检查不需要渲染就能发现的问题：

- 讲解目标、事实、数字和结论是否一致。
- 每句旁白是否有对应画面任务。
- 每个镜头是否只有一个理解重点。
- 时间轴是否存在空档、重叠、负时长或字幕时间错位。
- 用户素材是否存在、可读、比例正确、用途明确。
- 字体、图标、脚本和必要数据是否本地化并可加载。
- 时长、帧率、分辨率和音轨要求是否明确。

先修这些内容，再花渲染成本。

## 第 1 轮：静态帧和全时间轴覆盖

### 1. 每镜头关键帧

渲染每个镜头的开始、中间和结束帧。开头、结尾、最长字幕和素材最多的镜头必须包含在内。

检查主体、构图、文字、图标、素材、遮挡和入场出场状态。

### 2. 全片联系表

把抽帧按时间顺序拼成联系表，检查整片节奏、重复画面、空白镜头和视觉跳跃。

默认每 1 秒抽一帧。信息密集段落改为每 0.5 秒一帧。长视频按章节分别生成，不能只查开头。

联系表用于发现问题，不用于证明小字清晰。

### 3. 信息密集镜头的原尺寸帧

每个信息密集镜头至少输出一张最终分辨率帧。最长字幕、复杂图表、多个素材同框和关键结论必须原尺寸检查。

检查边缘裁切、字体回退、缺字、溢出、模糊、细线和字幕遮挡。

### 4. 转场和快速动作连续帧条

每种转场至少检查一次。机制变化、快速运动、镜头高潮和形变也要覆盖。

在转场前后约 0.6–1.0 秒内，每 0.1–0.2 秒取一帧。更快或更关键的动作继续加密。重点看转场起点、过程中和落点，不只看两张前后静态图。

可用 FFmpeg 从预览或成片生成证据，例如：

```bash
ffmpeg -ss 16.0 -t 0.6 -i preview.mp4 -vf "fps=10,scale=320:-1,tile=6x1" -frames:v 1 transition.jpg
```

按实际时间、画幅和帧数调整。需要判断文字和边缘时，改用原尺寸帧。

## 第 2 轮：低清完整预览

输出覆盖完整时间轴的低分辨率预览。降低渲染成本，不改变时间轴和镜头内容。

检查：

- 开头是否迅速进入主题；
- 当前画面是否跟当前旁白；
- 镜头顺序和节奏是否帮助理解；
- 是否有非预期静止、空白、跳帧或抖动；
- 运镜是否只是整页缩放；
- 转场是否由内容关系驱动；
- 结尾是否收束；
- 有音频时，字幕、画面和声音是否同步。

工具支持读取完整视频时，直接检查完整 MP4。工具不支持时，用全片联系表、低清预览和各运动段的连续帧条补足，并如实说明没有进行实时完整播放。

## 独立评审

优先让未参与制作的执行者评审。没有第二执行者时，另开一轮只看证据的评审，不边改代码边替自己打分。

向评审者提供讲解目标、时间轴、联系表、原尺寸帧、连续帧条和技术检查结果。要求按影响排序，而不是泛泛评价风格。

每个问题使用以下格式：

```text
时间点或镜头：
可见问题：
影响：
可能原因：
具体修法：
优先级：
```

优先处理“看不懂、读不完、主体不突出、运动不连贯、声画不同步、文件损坏”。列出全部阻断问题；一般保留 5–10 个高影响修复项，不为凑数编造问题。

## 集中返修与局部复查

1. 保留当前版本和评审记录。
2. 按根因归类问题，例如全局字号、统一字幕数据、共用缓动或素材路径。
3. 修改根因影响的所有镜头，不只修被抽中的那一帧。
4. 一轮集中完成高影响修改，避免无目的反复全渲。
5. 局部重渲受影响镜头，并包含相邻转场。
6. 对照返修前后的同时间点证据。
7. 检查修改是否引入新遮挡、新空档或节奏变化。

局部检查通过后，仍需全量导出。不能用局部通过代替最终成片通过。

## 最终 MP4 验收

### 第二轮全片复查

重新生成最终成片的全片联系表。复查上一轮问题及相邻镜头，确认没有只在预览里正常、最终导出却出错的情况。

至少完成两轮覆盖全片的检查。第一轮找结构和理解问题，第二轮验证返修和最终导出。

### 技术检查

运行：

```bash
python3 scripts/check_video.py <成片.mp4> --width 1920 --height 1080 --fps 30 --codec h264 --decode --blackdetect
```

按实际规格调整参数。用户要求无声时添加 `--audio forbidden`；需要配音或音乐时添加 `--audio required`。

检查分辨率、帧率、时长、编码、完整解码、非预期黑帧和音轨。长视频还要检查非预期静止和音画同步。

自动检查退出码非零时先处理，不要交付。检查脚本没有覆盖的项目仍要人工检查。

### 渲染稳定性

对改造后的确定性工程，抽查相同时间点重复渲染是否一致。检查暂停、跳转、重播和片段渲染后的状态。

页面错误、关键资源失败、字体缺失、图片未加载或 WebGL 上下文丢失都不能被静默忽略。

### 文字阅读时间

逐条确认必要文字完整可见的时间足够阅读。自定义 HTML 工程可实现等价于 `TEXTS(t)` 的检查接口，自动记录文字框、完整可见时段和阅读时长。

没有自动接口时，根据字幕和关键文字时间轴检查，并用连续帧验证。打字机效果应按完整文字计算，不要把逐步出现的每个字符当作新文本。

## 通过标准

只有同时满足以下条件才交付：

- 内容准确，镜头跟随讲解；
- 必要文字能看清并读完；
- 运镜、动作和转场经过连续证据检查；
- 用户素材使用正确，图形风格统一；
- 全片经过至少两轮检查；
- 高影响问题已返修并复查；
- 最终 MP4 完整解码，规格和音轨符合要求；
- 回复只报告实际完成的检查，并保留未检查项说明。
